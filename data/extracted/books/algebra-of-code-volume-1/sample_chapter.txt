     Natural Numbers from Scratch
                 The natural numbers are the familiar sequence of objects starting with 0, 1, 2, 3, . . .
                 and continuing without end. In F#, we can represent the natural numbers
                 up to 2,147,483,647 with the int type. (F# has a similar number of negative
                 int values, but these aren’t natural numbers.) F# also has a bigint type for
                 representing arbitrarily large whole numbers.
                      Our focus in this section is on creating an F# type that represents natu-
                 ral numbers in a much different way than int or bigint. It won’t be efficient
                 or practical for computations, but it will serve as a useful definition of natu-
                 ral numbers, which will allow us to concisely define many more mathemati-
                 cal concepts.
                      We’ll base our type on the following intuitive properties of the natural
                 numbers called the Peano axioms, which most mathematicians consider the
                 official specification of the natural numbers.
                 The Peano Axioms
                    The natural numbers are a collection of objects satisfying the following
                    properties:
                       P0. There’s a special natural number zero.
                       P1. For each natural number, there’s another natural number called
                            its successor.
                       P2. Zero is not the successor of any number.
                       P3. Every natural number other than zero is the successor of some
                            natural number.
                       P4. If two natural numbers are distinct, they have distinct succes-
                            sors.
                       P5. If we have a collection of some natural numbers that includes
                            successors of all its members, as well as the number zero, then it
                            is in fact the collection of all natural numbers.
                    Definitions of addition and multiplication are often included in the
                    Peano axioms as well; we’ll explore these in the following section.
                     The Peano axioms don’t say what a natural number is. For example,
                 they don’t specify that a natural number is a word, or a string of digits, or
                 any other kind of entity. Rather, they say how natural numbers behave. Namely,
                 the properties imply that the natural numbers fit into an infinite sequence
                 beginning with the special starting value, 0.
                     Inspired by the Peano axioms, let’s use the following Natural type to rep-
                 resent natural numbers:

                 type Natural =
                     | Z
                     | S of Natural

                 The case Z represents 0, and the case S is a function Natural -> Natural re-
                 turning the successor of a given value.
                      The simplest Natural value is the special zero value, Z. The successor of Z
                 is S(Z), which represents 1; the successor of 1 is S(S(Z)), which represents 2;

82   Chapter 4
    The Algebra of Code (Sample Chapter) © 2026 by Paul Orland

and so on. With a large enough text file, you could, in principle, represent
any natural number with enough applications of S.
     The values of the Natural type obey the Peano axioms: P0, P1, and P3 fol-
low from the definition of the type, and P2 and P4 are satisfied because of
the way structural equality works in F#. Specifically, structural equality for-
bids Z = S(m) for any Natural value m, and if m and n are distinct Natural values,
then S(m) and S(n) are distinct.
     Axiom P5 is perhaps the most cryptic, but it is also satisfied. For exam-
ple, if we have some Natural values including Z, and our collection contains
all successors of its members, then it must contain S(Z), and therefore also
S(S(Z)), and so on, ultimately telling us that every Natural value is in the col-
lection. Because the values of the Natural type satisfy the Peano axioms, we
can use the type as our definition of the natural numbers.
     This Natural type has marked disadvantages in practice. Even relatively
small numbers are hard to write or read as Natural values, as the following
example illustrates:

S(S(S(S(S(S(S(S(S(S(S(S(S(Z)))))))))))))

If we carefully count applications of S, we find this is the number we usu-
ally write as 13. To save ourselves effort, we can write functions toInt and
fromInt that convert from Natural to int, and vice versa. For instance, we want
toInt (S(S(Z))) to return 2 and fromInt 13 to return the value just shown.
     Like the List type, Natural is defined inductively, so we’ll often use recur-
sion when we write functions to work with it. Let’s start by implementing the
fromInt function:

let rec fromInt (i:int) =
    if i > 0 then
         S(fromInt (i-1))
    else
         Z

Here, we make use of the fact that fromInt n should be the successor of fromInt (n-1),
for n greater than 0. You can implement toInt in Exercise 4.1, using the prin-
ciple that for any Natural value n, toInt (S(n)) should equal 1 + toInt n.
     From here on, we’ll casually switch between F# code and mathematical
notation. In the latter, we’ll denote zero by 0 and the successor function by s.
For instance, s(s(0)) will mean the same thing as the F# value S(S(Z)). When
we write a number like 4, you can think of it as shorthand for an expression
like s(s(s(s(0)))) or its F# alternative, S(S(S(S(Z)))).

     Defining Arithmetic
                 Our next goal is to write arithmetic functions for the Natural type. We’ll im-
                 plement addition and multiplication as functions of type Natural -> Natural
                 -> Natural that take two numbers and return their sum or product, respec-
                 tively. Our functions will be written recursively in terms of 0 and the succes-
                 sor function, so they will define the arithmetic operations in terms of the
                 Peano axioms.

     NOTE        You may choose to organize the functions for the Natural type in a module of the same
                 name. The Natural.fsx file in the online source code gives an example.

                 Addition
                 Let’s start by implementing addition of Natural values. To do this, we’ll use
                 the idea that m + n should be the result of applying the successor function
                 m times to n. We can translate this to a recursive definition by considering
                 both cases for m: either m = 0 or m = s(k) for some natural number k.
                      We will handle the two cases with different addition rules. The first case
                 is the base case, when m = 0, for which we define the following:

                                                      0+n=n
                     The second possibility is the recursive case, m = s(k). Intuitively, s(k) is
                 one more than k, so s(k) + n should be one more than k + n. Therefore, we
                 use this as our addition rule in the recursive case:

                                                  s(k) + n = s(k + n)
                     Because k is smaller than s(k), we can be sure that the recursion always
                 terminates. Here’s an example that shows how to do addition by invoking
                 the base case and recursive case rules.

      The Algebra of Code (Sample Chapter) © 2026 by Paul Orland

Example: Computing 2 + 2
   Let’s use our definitions to compute 2 + 2. We have the following:

                    2+2     = s(s(0)) + s(s(0))       (Definition of 2)
                            = s(s(0) + s(s(0)))       (Recursive case)
                            = s(s(0 + s(s(0))))       (Recursive case)
                            = s(s(s(s(0))))           (Base case)
                            =4                        (Definition of 4)

      Notably, if we define 2 to mean the expression s(s(0)), 4 to mean the ex-
      pression s(s(s(s(0)))), and “+” according to the two rules, then this is a
      proof that 2 + 2 = 4.
      Our recursive addition procedure translates directly to F# as follows:

let rec add (m:Natural) (n:Natural) =
    match m with
    | Z -> n
    | S(k) -> S(add k n)

You can quickly confirm that adding S(S(Z)) to itself gives S(S(S(S(Z)))),
showing that 2 + 2 = 4.
   For a bigger test, it’s convenient to use the fromInt and toInt functions, as
shown next:

toInt(add (fromInt 40) (fromInt 50)) // returns 90

This converts the numbers 40 and 50 to Natural values, adds them using the
add function, and converts the output back to an int, resulting in 40 + 50 =
90.
     Notice, and remember for later, that the definition of addition and our
F# implementation are both asymmetric: m + n is computed by recursion
on m, not n. For instance, we have 0 + 3 = 3 by a single application of the
base case, but showing that 3 + 0 = 3 requires three recursive steps plus the
base case. Of course, past experience tells us that m + n should equal n + m
in general, but the two expressions mean different things. The fact that
m + n = n + m is something that needs to be proved; we’ll do that in “Prop-
erties of Arithmetic” on page 89.

                 Multiplication
                 Just as we implemented addition by repeated application of the successor
                 function, we can implement multiplication as repeated addition. Again, we’ll
                 define m · n recursively in terms of the possibilities for m.
                      Intuitively, m · n means we add m copies of n. The first case is that m is
                 0, which would mean that there’s nothing to add and that we define m · n =
                 0. The second, recursive case is that m = s(k) for some k, in which case m · n
                 should be k · n plus one more copy of n. That is, we can define the following:
                                                 s(k) · n = n + (k · n)
                 Again, k is smaller than s(k), so we can be assured this recursion terminates
                 for all inputs.
                      In F#, this translates to the following multiply function for Natural values:

                 let rec multiply (m:Natural) (n:Natural) =
                     match m with
                     | Z -> Z
                     | S(k) -> add n (multiply k n)

                 Just as the addition m + n boils down to applying the successor function m
                 times to n, the multiplication m · n is carried out by adding n with itself m
                 times.

Subtraction
Let’s turn to subtraction. We can define the difference n – m of natural num-
bers n and m to be the natural number d such that m + d = n, if such a d ex-
ists. For instance, 5 – 3 = 2 because 2 is the number we add to 3 to get 5.
Some natural number differences, like 2 – 7, don’t exist. Here, the problem
is that 7 is greater than 2, so there’s no natural number d making 7 + d = 2.
Here’s a proof of a smaller example, directly from the Peano axioms.
Example: Proving that 0 – 1 is not a natural number
   Let’s prove that 0 – 1 is not a natural number. If there were a natural
   number d such that 0 – 1 = d, then by definition of subtraction we’d have
   0 = 1 + d. Using the definition of addition, this gives us
                          0 = 1 + d = s(0) + d = s(0 + d) = s(d)
    making 0 the successor of d. By the Peano axiom P2, 0 is not a succes-
    sor, so there can be no such d after all.
    You can try writing down a similar proof in Exercise 4.12.

    To implement subtraction for Natural values in F#, we need to consider
the possibility that the result is undefined. Without negative numbers at our
disposal, we can implement subtraction as a function that takes two Natural
values and returns a Natural option. This function returns Some if there’s a
natural number result, or None otherwise.
    The following trySubtract function takes inputs m and n and returns n –
m (that is, the second input minus the first):

let rec trySubtract (m:Natural) (n:Natural) : Natural option =
    match m,n with
    | Z,_ -> Some(n)
    | S(k), Z -> None
    | S(k), S(l) -> trySubtract k l

This ordering of inputs may seem odd, but it’s chosen so that a partial appli-
cation like trySubtract m does what it sounds like: It takes an input and tries
to subtract m. (Of course, you’re welcome to use whatever ordering you like
in your own implementation!)

                 Division
                 The final basic arithmetic operation is division. For natural numbers n and
                 m =/ 0, their quotient is written n ÷ m or n/m, and it’s defined to be the num-
                 ber q such that m · q = n, if such a number q exists. For instance, 10 ÷ 2 = 5,
                 which means 5 · 2 = 10. To indicate that the quotient 10 ÷ 2 exists, we say 2
                 divides 10, or 10 is divisible by 2.
                      By contrast, there’s no natural number q such that 2 · q = 3, so 3 ÷ 2
                 is not defined; 2 does not divide 3. As a matter of definition, we don’t al-
                 low division by 0; we don’t give any meaning to an expression like n ÷ 0.
                 Combining these facts, you can try to write your own function to divide one
                 Natural by another. Since the quotient is not guaranteed to exist, you can use
                 Natural option for the return type.
                      Another variant you may remember from elementary school is divi-
                 sion with a remainder. For natural numbers n and m =/ 0, m may not divide

                 Mathematical Induction
                 For a motivational example, let’s consider the right identity property of ad-
                 dition: a + 0 = a for all natural numbers a. This makes a good first example
                 because it’s “obviously” true, but it’s not obvious how to prove it from the
                 definitions. Here’s a first try.
                 Proof attempt: The right identity property of addition
                    Let’s try to show a + 0 = a for all natural numbers a by using the def-
                    inition of addition. By the Peano axioms, either a = 0 or a = s(k) for
                    some natural number k. In the first case, we have 0 + 0 = 0, which is
                    true by the base case of addition. In the second case, we’d like to show
                    s(k) + 0 = s(k). By the recursive case, we have this:

                                                         s(k) + 0 = s(k + 0)

                     But to complete the proof, we’d need to show k + 0 = k for any natural
                     number k. We’re back where we started!
                     The root of the problem is that when we’re trying to prove a + 0 = a,
                 we’re actually trying to prove an infinite collection of facts at once. The se-

                            Fact 0:        0+0     = 0
                            Fact 1:        1+0     = 1
                            Fact 2:        2+0     =    2
                            Fact 3:        3+0     = 3
                            Fact 4:        4+0     = 4
                               ..                  ..
                                .                   .
and continues infinitely, with one fact per natural number. Proving any of
these individually is no challenge. Here, for instance, is a proof of Fact 4.
Proof: 4 + 0 = 4
   We use four applications of the recursive case for addition, plus one ap-
   plication of the base case:

                              4+0     = s(s(s(s(0)))) + 0
                                      = s(s(s(s(0))) + 0)
                                      = s(s(s(s(0)) + 0))
                                      = s(s(s(s(0) + 0)))
                                      = s(s(s(s(0 + 0))))
                                      = s(s(s(s(0))))
                                      =4

     The key observation we can make is that the second line, s(s(s(s(0))) + 0),
is equal to s(3 + 0). If we had already proved Fact 3, which says 3 + 0 = 3, we
could have finished the proof in one step here. It turns out this happens in
general: If we use Fact n, we can easily prove the subsequent Fact s(n).
Proof: Fact s(n) from Fact n
   Suppose we know Fact n from our list—that is, n + 0 = n. Then, using the
   recursive case of addition and Fact n, we show

                                s(n) + 0 = s(n + 0) = s(n)

    which is Fact s(n).
     This principle convinces us that we could prove any fact in the list. Sup-
pose we wanted to prove Fact 1,000,000. We know Fact 0 is true, since 0 +
0 = 0. We can then use Fact 0 to prove Fact 1, Fact 1 to prove Fact 2, Fact 2
to prove Fact 3, and so on, until eventually we use Fact 999,999 to prove
Fact 1,000,000. The logical jump from here is that in showing we could prove
any of the facts, we have proved all of them.
     The principle of mathematical induction is that if we have a sequence of
facts where the first one is true and each fact implies the next, then indeed
all the facts in the sequence are true. This follows from Peano axiom P5, as
the following proof shows for the specific example of a + 0 = a.

                 Proof: The right identity property of addition

                 Inductive Proofs of Arithmetic Properties
                 Mathematical induction can be mind-bending, but in practice it’s quite sim-
                 ple to use for proving facts about natural numbers. If we want to prove some-
                 thing about every natural number, we just have to show that it’s true for 0
                 and that if it’s true for some n, it’s true for s(n) as well.
                      With this technique in hand, it’s possible to prove all the arithmetic
                 properties from Table 4-1. Here are two examples, starting with the asso-
                 ciative property of addition.
                 Proof: The associative property of addition
                    Let’s prove that (a + b) + c = a + (b + c) for all natural numbers a, b, and c.
                    Our strategy is to fix b and c and use mathematical induction to prove
                    the fact for all a.
                         First, we want to show the fact holds for a = 0. We have

                                              (0 + b) + c = b + c = 0 + (b + c)

                     using the base case of addition twice.
                         Second, let’s assume that the result holds for a = k—in other words,
                     that (k + b) + c = k + (b + c)—and show that the result holds for a = s(k). In-
                     deed, we have the following:

                                             (s(k) + b) + c = s(k + b) + c
                                                             = s((k + b) + c)
                                                             = s(k + (b + c))
                                                             = s(k) + (b + c)

                                          = s(k + s(n))
                                          = s(k) + s(n)
                                          = m + s(n)

    We use the recursive case for addition on the second and fourth lines,
    and the induction assumption s(k) + n = k + s(n) on the third line. By
    mathematical induction, the proof is complete.

tion: m + n = n + m for all natural numbers m and n.

                 The integers are the infinite collection of numbers

                 including all the natural numbers as well as a “negative” copy of each nonzero
                 natural number. For a precise definition, the idea will be to define –n as the
                 answer to the subtraction problem 0 – n, which had no natural number solu-

                      We can almost think of the integers as two conjoined copies of the nat-
                 ural numbers, one positive and one negative. We just have to be careful not
                 to include 0 and –0 as two different values. In this section, we’ll work around
                 this issue to implement an Integer type whose values are in one-to-one corre-
                 spondence with actual integer values, along with arithmetic functions to go
                 with it.


                 An Integer Type
                 For our Integer type, we’ll use the following discriminated union, including
                 two copies of the Natural type to represent the positive and negative integers,
                 respectively:

                 type Integer =
                     | Positive of Natural

    | NegativeS of Natural

To avoid duplicating the value 0, we’ll interpret Positive(n) as the natural
number n and NegativeS(n) as the negative successor of n, that is, –s(n) or
–(1 + n). For instance, Positive(Z) is 0 and Positive(S(Z)) is s(0) = 1, while
NegativeS(Z) is –s(0) = –1 and NegativeS(S(Z)) is –s(s(0)) = –2.

but we can also view the symbol as an operation that takes an integer and re-

let negate (x:Integer) : Integer =
    match x with
    | Positive Z -> Positive Z
    | Positive(S(n)) -> NegativeS(n)
    | NegativeS(n) -> Positive(S(n))

How We Usually Represent Numbers
       Let’s make the connection between our custom implementations of num-
       bers and arithmetic, and the way we work with numbers in real life. Humans
       and computers don’t usually work with numbers in terms of 0 and the suc-
       cessor function. Instead, we use a place-value system, where numbers are
       strings of digits 0 through 9 and the position of each digit determines its
       contribution to the overall number value. For instance, the number 1,905 is
       short for a sum of powers of 10, as illustrated here:

                    1,905 = 1 · 1,000 + 9 · 100 + 0 · 10               + 5·1
                             = 1 · 103         + 9 · 102   + 0 · 101   + 5 · 100

       This system is called base 10, or decimal, because there are 10 digits, and the
       digits in a number contribute various powers of 10. Alternatively, we can
       choose any other base b ≥ 2, where we select b symbols as digits and they
       contribute powers of b according to their position. The most important ex-
       ample is base 2, or binary, where the digits—called bits in this context—are the
       two symbols 0 and 1.
            We sometimes use a subscript to clearly indicate the base we’re working
       in (so 101112 means 10111 interpreted as a base 2 number), while omitting
       the subscript means we’re using base 10. For example, the binary number
       101112 is equal to the decimal number 23:

                  101112    = 1 · 24     + 0 · 23    + 1 · 22   + 1 · 21   + 1 · 20
                            = 16         + 0         + 4        + 2        + 1
                            = 23

            I’ll assume you’re familiar with these ideas, so I won’t belabor the topic.
       In a few places in the book I’ll mention numbers in base 2 or other bases,
       so if you want a refresher, try the next exercises. A first challenge (Exer-
       cise 4.29) is to interpret an int list of digits like [1;0;1;1;1] in a given base,
       converting it to the int value it represents. For instance, viewed as a binary
       number, this should convert to 23, while viewed as a decimal number, it
       should be 10111. In base 3, it is a different number again: 101113 = 94. After
       you can convert both ways, you can try implementing addition, subtraction,
       and multiplication in any base by using the elementary school techniques of
       carrying, borrowing, and so on. As a general hint, you may find it easier to
       recurse on lists of digits if you reverse them.
            Lists of digits or bits are much more efficient for calculations than the
       Natural type. For example, adding two 10-digit numbers as Natural values

Rational Numbers
       By including negative numbers, we were able to define subtraction for any
       pair of integers. If we further include fractional numbers, we get the rational
       numbers, a set in which any division (except by 0) is defined.
            For two integers x and y =/ 0, we can write their quotient x/y, even if there
       is no such integer. We declare every such quotient to be a rational number,
       with x as the numerator and y as the denominator. Every integer x corresponds
       to a rational number x/1, but some rational numbers, like 1/2, don’t corre-
       spond to any integer.


       A Rational Type
       We can represent rational numbers in F# with a pair comprising an inte-
       ger numerator and integer denominator. If you want to keep working from
       scratch, you can use Integer values, but for simplicity and efficiency, we’ll use
       the F# bigint type from Exercise 4.36:

       type Rational =
           {
               Numerator : bigint
               Denominator : bigint
           }

           To create a bigint value, we end our number with the character I, so that
       the following represents the number 10/5:

       { Numerator = 10I; Denominator = 5I}

            The values of this Rational type are not in one-to-one correspondence
       with the rational numbers. One problem is that the Denominator could be
       zero (0I), giving us a Rational that doesn’t represent a valid rational number.
            Another issue is that there are many ways to represent any given rational
       number as a Rational. For instance, 10/5 and 2/1 should be equal as rational
       numbers, because they are equal as quotients of integers. In mathematics,
       this ambiguity is handled by redefining equality for rational numbers: We
       say a/b = c/d if ad = bc. This notion of equality is not captured by structural
       equality of Rational values, so if we want to test equality of Rational values in
       F#, we need to use our own test function, like the following:

       let equal (q:Rational) (r:Rational) =
           q.Numerator * r.Denominator = r.Numerator * q.Denominator

                       In F#, it’s actually possible to overload the = sign to mean a custom equal-
                  ity test for a given type, but for transparency we will avoid doing so in this
                  book. Whenever we write an equal sign in F# code, you can be assured we’re
                  talking about structural equality.
                       Another way to test equality for rationals is to write them in reduced form,
                  with their denominators as the smallest positive integers possible. For in-
                  stance, 256/192 and 20/15 both have the reduced form 4/3, while 16/ – 32
                  has the reduced form –1/2. Reduced form is a normal form, meaning that
                  two integer quotients represent the same rational number if and only if their
                  reduced forms are structurally equal. Thus, another way to test equality for
                  Rational values is to convert them to their reduced forms and compare them
                  using the = operator.
                       We can compute the reduced form of an integer quotient x/y by divid-
                  ing both x and y by their greatest common divisor, or the largest natural num-
                  ber d that divides both x and y, as follows:

                  let reduce (q:Rational) =
                      let sign = if q.Denominator < 0I then -1I else 1I
                      let gcd = bigint.GreatestCommonDivisor(q.Numerator, q.Denominator)

                       Here’s a brief, informal description of how this works. Let’s define a
                  real number x as a well-defined cutoff point among the rational numbers, in
                  the sense that we can take any rational number r and say whether r < x. We
                  say two cutoff points√x and y are the same if r < x whenever
                                                                            √ r < y.
                       As an example, 2 is a real number: We define a < 2 if a is negative or
                  if a2 < 2. Every rational number x is also a real number. It defines a cutoff
                  point, where r < x has its usual meaning.
                       A real number x, viewed as a cutoff point, is a machine that takes a ratio-
                  nal number r and returns whether r < x is true or false. As such, it’s thought-
                  provoking to define the type

                  type Real = Rational -> bool

                  where each real number would be represented by the function returning
                  true for all the functions below it. Indeed, every real number can be viewed
                  as a function that takes a rational number and returns a Boolean value.
                       This is a cool functional perspective, but it’s not so useful in practice.
                  Not every function Rational -> bool defines a cutoff point, and it turns out
                  that for most real numbers, we can’t write down their cutoff function ex-
                  plicitly. Even if we could represent real numbers as cutoff functions, it’s not
                  clear how to do arithmetic with them. (Can you figure out how to add or
                  multiply two values of the Real type we just defined, in general?)
                       Despite its impracticality, the Real type is a nice bookend to our project
                  of constructing number systems in F#. We implemented natural numbers
                  and integers as discriminated union types, rational numbers as a record
                  type, and now real numbers as a function type, so we’ve used all the essen-
                  tial algebraic data types in F#!

Summary
        In this chapter, we used the F# type system to implement some basic math
        from scratch. Namely, we created types representing various kinds of num-
        bers and functions to do arithmetic operations with them.
             We started by creating a Natural discriminated union to represent every
        natural number 0, 1, 2, . . . as either the special value Z, meaning 0, or the
        successor S(m) of another natural number m. We wrote functions to add, sub-
        tract, multiply, and divide Natural values, without using the built-in int type
        or its operations. Because we worked from scratch, we were able to take our
        arithmetic functions as definitions and prove facts like 2 + 2 = 4. Using the
        principle of mathematical induction, we then proved more general prop-
        erties about arithmetic, such as the fact that m + n = n + m for any natural
        numbers n and m. Facts like this are our basic tools in algebra.
             Next, we created an Integer type as a discriminated union of two copies
        of the natural numbers, representing positive and negative numbers, re-
        spectively. We further extended the integers to define the rational num-
        bers, which include the integers as well as fractions. Our Rational type was a
        record storing two integers, representing integer quotients of the form a/b.
             Finally, we explored a more subtle collection of numbers: the irrational
        numbers, which can’t be expressed as fractions or finite decimal expansions.
        Both rational and irrational numbers can be expressed as cutoff points of ra-
        tional numbers, so we modeled real numbers as predicates of type Rational -> bool,
        indicating whether a rational number was above or below the cutoff.
